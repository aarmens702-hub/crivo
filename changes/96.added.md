`CRIVO_KERNEL_DENY_READ` (JSON `{"deny": [...], "allow": [...]}`) makes a subprocess kernel refuse, with a `PermissionError` and a line in the supervisor's stderr log, any cell that reads, lists, copies, moves or imports from a denied path or starts a process; it is a speed bump, not a sandbox: native readers, ctypes, metadata calls, `dir_fd`-relative opens, a symlink race and code that patches the guard all get past it, and a cell can still write wherever its user can outside the denied paths (site-packages, a `.pth` file, an editable crivo's source, the kernel's working directory), planting code that runs later.
