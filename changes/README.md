# Changelog fragments

One file per user-visible change, named `<issue#>.<kind>.md`, where kind is
`added`, `changed`, `fixed`, `removed` or `security`. One line, written for a
user: what changed and what they do differently. `/promote` folds them into
CHANGELOG.md and deletes them. Internal changes (tests, docs for maintainers,
refactors) get no fragment.
