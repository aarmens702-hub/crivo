## North star

**crivo: numbers you can bet on.** A full data analyst that is also a tool
other agents use: it cleans, explores, charts, tests, segments, forecasts and
explains. It works data in a live, contained Python kernel, never in a
model's context. Every result it calls **backed** has passed checks by a
referee the work cannot touch. When it cannot prove something it says so or
asks. What works becomes governed skills and memory that stay checked as data
changes, and it explains in plain language what it did and why the result
holds.

**Headline metric: the false-backed rate**, the share of results called
backed that are wrong against known truth, published with its sample size and
confidence interval, beside the backed rate and the cost per backed answer. It
is measured on suites crivo built, on external benchmarks, and on wrong
answers real users report. A rising backed rate never excuses a rising
false-backed rate.

## Rules that order everything

1. **The instrument comes before the capability it measures.** Every stage has
   a gate with numbers; the next stage starts only when the gate passes.
2. **The referee is untouchable.** Nothing the model, the kernel, the data or a
   learning loop can write changes a verdict. Everything the referee trusts
   (baselines, contracts, glossary, skills, saved answers, the ledger) lives
   outside what kernel code can write. Enforced mechanically, never by prompt.
3. **No unattended model code without containment.** Paths that run model code
   with no person reading it (`crivo.ask`, MCP `ask` and `clean_file`, headless
   `clean`, the autonomous level) require the stage 0 containment.
4. **Bugs do not wait.** A known defect is fixed in the stage it is assigned
   to, not deferred to a feature.
5. **Core changes are reviewed diffs.** `loop.py`, `prompts.py`, `llm.py`,
   `card.py`, `skills.py`, `library.py`, `provenance.py`, `detect.py` stop for
   Aarmen's yes.
6. **Independence.** Whoever writes a test of crivo does not read what it
   tests: injector authors never read `detect.py` or `autoclean.py`; trap-suite
   authors never read `prompts.py` or the referee; a learning loop never reads
   the generator, the scorer, the truth or the held-out sets.
7. **Real data and real users.** Every stage is dogfooded on real data with a
   recorded artifact, and from stage 1 on, design partners use it and can report
   a wrong answer.
8. **Formats are promises.** Every file crivo writes into a user's repo or CI
   carries a schema version and follows the deprecation policy.
9. **The contract moves with the code.** `docs/API-CONTRACT.md` is updated in
   the same change as any flag, env var, command, tool or format it lists.
10. **Work flows through the EDISON workflow, by work type (AGENTS.md):** a
   WRAP spec per stage; issues via `/new-task`, each with a type; code built
   via `/start-task`; behaviour judged by a pre-registered `/eval` result in
   the ledger; eval suites written by an author who did not read what they
   test; experiments recorded, then adopted or dropped; shipped to `dev` via
   `/ship`, moved to `main` via `/promote`.

## Memory

crivo builds its own memory rather than using a memory product, because generic
memory stores unverified text that a model can write anything into. One rule:
**the model proposes; a person, or a check that ran, makes an entry binding.**

| Memory | Holds | Stage |
|---|---|---|
| **Working** (one session) | Data and results as kernel variables; compaction that keeps pointers to earlier answer cards and transcript events | 1 |
| **Semantic, per dataset** | Contracts: meaning, canonical choices, grain, keys, units, time zone, locale formats, known traps, past clarifications | 1 |
| **Semantic, per project** | The glossary: definitions spanning datasets (fiscal calendar, week start, reporting time zone, "active customer", currency and its FX rate source, rounding) | 2 |
| **Procedural** | Skills: fixes and analysis recipes, test-gated, kept only while they beat no-skill | 2 |
| **Episodic** | Saved answers (stage 2); the provenance ledger and transcript (exist today) | 2 |

Rules for every memory:
- **Binding or pending.** Every entry records its source and who confirmed it
  (git identity). Only binding entries are used by the referee.
- **Files in the repo, merge-safe** (one file per entry where conflicts are
  likely), versioned (rule 8) and reversible by id; every learned entry declares
  its expected outcome. CODEOWNERS can guard `contracts/` and the glossary.
- **Outside the kernel's reach** (rule 2).
- **Checked against new data** by `crivo verify`; a contradicted entry is
  flagged, not trusted.
- **Retrieval is deterministic first** (dataset fingerprint, column name), then
  System 1 ranking for recipes. No embedding search over raw values.
- **No rows.** Memory holds meanings, rules and code. Transcripts, snapshots and
  workspaces do hold values, so they are never committed: `crivo init` writes
  the gitignore, and workspaces have a retention rule.

## Stage 2: the analyst toolkit and learning, in parallel

Two independent tracks with their own gates. Toolkit results become recipe
skills, so the tracks feed each other.

### 2a. The analyst toolkit

**Goal:** the analysis a full analyst does, as deterministic functions the
model chooses and calls. The model never computes a statistic or a forecast
itself; each function returns its result with receipts the referee checks.

- **Statistics** (B1.1): t-tests, Mann-Whitney, chi-squared, ANOVA and
  Kruskal-Wallis, correlation with significance, bootstrap confidence
  intervals, effect sizes, multiple-comparison correction. The test is chosen
  by assumption checks (normality, equal variance, sample size) that ship on
  the card.
- **Drivers:** mix-vs-rate decomposition for ratio metrics (B1.2) and
  contribution analysis, beside today's sum decomposition.
- **Segments:** rule-based segmentation and simple clustering on stated
  features, cohorts, retention curves, funnels, RFM.
- **Time series:** decomposition (STL), seasonal-naive and statsforecast
  baselines, forecasts with intervals and rolling-backtest receipts (B4.4,
  pulled forward from Later).
- **Anomalies and drift:** metric anomaly detection (robust and seasonal),
  drift statistics in `compare` (PSI, KS, JS) (B3.3, pulled forward).
- **Dashboards and reports:** a self-contained page of backed charts and
  answers, and markdown for pull requests, refreshed by `crivo verify` once 2b's
  saved answers exist.
- Dependencies (scipy, statsmodels, statsforecast) ship as an extra so the
  keyless core stays light (D25).

**Gate:** a toolkit suite with known answers, built by authors who did not read
the toolkit: datasets with planted effects and with none (a no-effect case must
not come back significant at more than the stated rate), seasonal series with
known forecast error bounds, cohort tables with hand-computed retention, ratio
metrics with a known mix shift. False-backed rate on statistical claims under
the D19 threshold.

### 2b. Learning

**Goal:** what works is kept, stays checked, earns its place, and is shared.

- **System 1 arrives here:** the `decide()` seam, local-first (R4.3), calibrated
  on crivo's own corpus before use, its probabilities shown as receipts, never a
  verdict. Its first job is the owner's intent for Jev: the **cheap first stage
  of the learning loop's evaluation cascade** (is a proposed shape plausible,
  which skill does a failure belong to, rank candidate edits), with the referee
  as the final word.
- Fix and recipe skills, counterfactual rent, a negative-transfer probe,
  declared expected outcomes, Agent Skills export built on
  `scripts/export_skills.py` (R5.1 to R5.4); content-digest admission (`RFf`);
  a person's rejection never counts as a verification failure (regression test);
  `scripts/ablate_governance.py` as the baseline for counterfactual rent, then
  retired.
- **Skill supply chain:** importing a skill records its origin, pins its digest
  and re-admits it on local held-out cases before it runs. A pending-admission
  queue for skills born from outside agents' fixes; a proven skill answering
  without a model call (old T3.3). Harmonize and family-mode mappings become
  recipe skills.
- **Project memory:** the glossary (fiscal calendar, week start, reporting time
  zone, metric definitions, currency with a named FX rate source and as-of
  rule, rounding), binding and pending like contracts.
- **Team use:** who may make an entry binding and how identity is recorded;
  merge-safe formats; the skill ledger committed, not gitignored.
- **Saved answers and `crivo verify`** (R5.5 to R5.7): source binding (a glob,
  this month's file, a named connection, a partition); still backed, broken,
  drifted, with thresholds and history defined; the Action `verify` mode with
  PR-comment output; a webhook; recurring reports (saved answers rendered to
  markdown or HTML, refreshed by `verify`); verified-answers memory (A3.3);
  OpenLineage events (B5.2).
- **The rest of the learning loop** (R5.8, R5.9): shape generation, detector and
  fixer improvement as review branches (start with d23 and d18), then **nightly
  skill improvement**. Keep conditions: strict improvement on held-out data,
  paired per seed, no per-detector regression, collateral and None-excluded
  counts never rising, threshold-only changes needing held-out-shape gains,
  reproduction in a fresh session, survival under ablation, a jump alarm, a
  noise floor, a simplicity prior, a rejected-edit memory, and an LLM plus human
  review of diffs for constants that mirror the generator. Mined prompt tips
  per disease, kept only if the bench rises with the external sets held out.

**Gate (2b):** skills beat no-skill on held-out cases; `verify` catches planted
breaks (duplicates, late records, retries) and memory entries the new data
contradicts; a glossary term is answered with its binding definition; kept
loop edits hold on the sealed set and the external datasets; an imported
foreign skill that fails local re-admission never runs.

## Stage 3: backed SQL and scale

**Goal:** the same guarantees over databases and data bigger than memory.

- Read-only connections from the project config, cost guard, pushdown,
  `sqlglot` (R2.3 to R2.5); warehouses and cloud paths via fsspec (old P2.3,
  P2.5, B2.2), with the remote fetch caps (`CRIVO_HTTP_TIMEOUT_S`,
  `CRIVO_HTTP_MAX_BYTES`) kept; joins across a file and a database in one answer.
- The 26 checks over DuckDB, so `crivo diagnose` works on a 5 GB parquet folder.
- The referee's SQL checks: fan-out, key uniqueness and null keys, grain, the
  second path.
- Relational and temporal correctness (the P7 packets): FK orphans and
  join-aware dedupe (28), the temporal check (27) and `Report.temporal`,
  arithmetic and 3+ column dependencies, end-before-start; reconcile shows its
  excluded keys (D13).

**Gate:** our own SQL trap suite on a seeded warehouse; false-backed rate under
the D19 threshold for SQL answers; diagnose over a 5 GB folder within a stated
budget; Claude Code using crivo against plain Claude Code on the same suite.

## Stage 4: labelling at scale (only if the gap is shown)

**Starts only if** the tabular OOLONG suite built in stage 1 shows answers crivo
cannot back without labelling.

  validation, spot-check; off in headless mode, opt-in per column, person-graded
  the first time; a host-enforced per-question token and dollar budget. Absorbs
  free-text categorization (B4.5).
- More System 1 uses: the intent pre-filter (a frozen, hashed set of 100 to 200
  triples; arms for Jev, an open decision model and Haiku; randomized option

  semantic-role classification; d07 and d12 clustering; confidence as evidence

- PII names and addresses for the label screen; masking as a gated fix (B0.1).
- Decisions: local model size (D14; no Jev-distilled models, and never log Jev
  outputs for training), the privacy rule for sending values (D15).

**Gate:** the tabular OOLONG suite; the intent-check evaluation; label
agreement on spot-checks published.
