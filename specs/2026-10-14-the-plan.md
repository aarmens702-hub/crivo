## North star

**crivo: numbers you can bet on.** A data analyst that is also a tool other
agents use. It works data in a live Python kernel, never in a model's context,
and every number it calls **backed** has passed checks by a referee the work
cannot touch. When it cannot prove something it says so or asks. What works
becomes governed skills and saved answers that stay checked as data changes.

**Headline metric: the false-backed rate**, the share of results called backed
that are wrong against known truth. Published with the backed rate and the
cost per backed answer. A rising backed rate never excuses a rising
false-backed rate.

## Rules that order everything

1. **The instrument comes before the capability it measures.** Every stage has
   a gate; the next stage starts only when the gate passes.
2. **The referee is untouchable.** Nothing the model, the kernel or a learning
   loop can write changes a verdict. Enforced mechanically, never by prompt.
3. **Bugs do not wait.** A known defect is fixed in the stage it is assigned
   to, not deferred to a feature.
4. **Core changes are reviewed diffs.** `loop.py`, `prompts.py`, `llm.py`,
   `card.py`, `skills.py`, `library.py`, `provenance.py`, `detect.py` stop for
   Aarmen's yes.
5. **No public release without a sandbox story.** The P0 residual (a kernel
   cell can read files the user can, and MCP `ask` runs model code as the
   server user) is decided before stage 5 ships.
6. **Dogfood every stage on real data,** not only on dirt we designed.
7. **Work flows through the EDISON workflow:** a short WRAP spec per stage,
   issues via `/new-task`, built via `/start-task`, shipped to `dev` via
   `/ship`, moved to `main` via `/promote`.

## Stage 0: the honest foundation

**Goal:** make the instrument and the verdicts true before anything is built on
them. Three parts, in order.

**0a. The honest scorer** (no core files)
- Measured zeros score 0, so repair F1 reports its honest value (0.596, not
  0.923) (`DD2`); "repair undefined by design" becomes a declared, counted rule.
- Invariants that can fire, and degenerate strategies (wipe a column, refuse
  all, drop the column, sort and reset) that must never beat no-op (`T28`).
- The bench driver stops auto-running GATE and PLAN gates (`T13`).
- An append-only experiment ledger keyed by git commit, corpus hash and scorer
  hash; bench rows record the model that served them; arm suffix migration
  (`DD3`, decision D6).
- Variety: a held-out split by *kind* of dirt; a hand-built property-based
  shape generator (hypothesis, no LLM yet); the injector and fixer stop sharing
  a vocabulary; CITBench added beside the Raha sets; multi-label truth
  (`BT2`, decision D5).
- Per-detector precision, recall and F1 published.
- The autonomous-vs-careful numbers the autonomy packet never produced.

**Loop 1: red-team the scorer** (the first autoresearch loop, v2 R5.8 step 1)
- An agent in its own worktree may write only `bench/attacks/`. Hooks deny it
  reads and writes to the scorer, the truth files, the held-out sets and (once
  it exists) the referee; their hashes are checked at every keep.
- Objective: find a cleaned frame or a cleaner for which the published numbers
  disagree with an independent recomputation, or for which a degenerate cleaner
  beats an honest one. Reward is distinct confirmed lies.
- Every find becomes a red regression test before its fix. Runs again after
  0b, aimed at the referee.

**0b. The referee** (R1.1 to R1.5 of the v2 design)
- Baselines on the host; the reproduced bypass becomes a red test, then green
  (`T15`/`a`).
- Collateral, idempotency, replay, grounding; a fix cannot corrupt its own
  target column and verify (`P2r1`; needs cell- and row-level evidence from
  `detect.py`, decision D7).
- Cards stamp only checks that executed (`T25`); the intent check fails closed
  on anything but an explicit match (`T29`); `clean()` reports failure after a
  failed diagnosis (`T30`); plan policies scoped per run with distinct ids and
  the reject note kept (`T12r`).
- Verdicts: backed, partly backed, not backed.

**0c. Detector honesty**, each change landing with a corpus case
- Silent caps reported as partial scans (`T42`); AUTO on ambiguous values
  (`T43` `T44`); evidence that overstates (`T45`); NaN coordinates (`T46`);
  mojibake false positives on real names (`T47`); the Excel title row (`T48`);
  AUTO grades on findings autoclean always refuses, d09 included (`P2r2`, `k`,
  decision D4); the d6 internal-space verdict (`BT3`, decision D8).

**Gate:** `hospital` and every external set report real numbers; no degenerate
strategy beats no-op on any published number; the red-team loop, run against
the scorer and then the referee, finds at least one lie (fixed) or returns a
clean bill; the bypass test passes; every
0c change shows its effect on per-detector numbers; false-backed rate measured
and published for cleaning.

## Stage 1: a backed answer over a file

**Goal:** the analyst answers questions over CSV and parquet with backed
numbers, asks when a question is ambiguous, and abstains when it cannot answer.

- The kernel toolbox and bridge (R2.1); DuckDB over files, lazy for large
  frames (R2.2); outputs to new files only (R2.6), versioned per gate so a
  revert stays true once fixes write files (A4.2).
- Dataset contracts with binding and pending entries, clarify, abstain
  (R3.1 to R3.6), with an ODCS v3.1 export (B5.1; decision D9 on format).
- The referee's answer checks: grounding, replay, contract conformance, second
  path (decision D10 on who writes it).
- Fix turns may explore read-only before writing a fix (kernel audit gap 1).
- Several frames and joins in one question (old P3.4).
- Prompt doctrines and restore-before-bootstrap with a model-visible note
  (`docs/p3-core-diffs-2026-09-02.md` §2 and §4, prime-agent §2), plus the
  compaction note that kernel variables survived (decision D11);
  `Session.peek` or a bounded result payload (§3).
- Export an answered session as a replayable notebook or script (old Ph8
  replay, B3.2 answer cards).
- Model choice by cost per backed answer (R4.1, R4.2): served-model recording,
  the provider hardening items (`RFe`), a per-provider smoke matrix, then the
  bake-off (Haiku 5.5, DeepSeek V4.1 Flash, GPT-6.1 Sol, Sonnet 5.5, Opus 5.5 as
  ceiling, one local model) with cost and wall-clock columns (A4.3).
- The fate of plan-first (M2-full planner and replan, or remove the flag;
  decision D12).

**Gate:** a trap suite built on real data (competing revenue columns, stale
flags, unlinked identities, unanswerable questions) plus a DABstep subset;
false-backed rate near 0; **crivo compared against plain Claude Code with
pandas on the same suite** (this replaces the old pandas-ai baseline); the
first full-corpus agent run published with an agent column in `RESULTS.md`.

## Stage 2: learning

**Goal:** what works is kept, stays checked, and earns its place.

- Fix and recipe skills, counterfactual rent, a negative-transfer probe,
  declared expected outcomes, Agent Skills export (R5.1 to R5.4); content-digest
  admission (`RFf`); `schema_version` and atomic writes on skill and provenance
  records (`RFb`).
- A pending-admission queue for skills born from outside agents' fixes (old v2
  toolkit fork 2); a proven skill answering without a model call (old T3.3).
- Saved answers, `crivo verify` with still backed, broken and drifted, the
  GitHub Action `verify` mode, and a webhook on failure (R5.5 to R5.7, B5.3);
  verified-answers memory (A3.3); OpenLineage events for applied fixes and
  saved answers (B5.2).
- The rest of the offline learning loop (R5.8, R5.9; loop 1 already runs in
  stage 0): shape generation, then detector and fixer improvement as review
  branches, then **nightly skill improvement** (replay failures on frozen cases,
  bounded edits to `fix.py`, keep only on strict held-out improvement with no
  regressions, a person admits). Recipe skills start with file answers; SQL
  recipes join when stage 3 lands.

**Gate:** skills beat no-skill on held-out cases; `verify` catches planted
breaks (duplicates, late records, retries); the nightly loop's kept edits hold
on the sealed held-out set and the external datasets.

## Stage 3: backed SQL and scale

**Goal:** the same guarantees over databases and data bigger than memory.

- Host-held read-only connections, cost guard, pushdown, `sqlglot` (R2.3 to
  R2.5); warehouses (Postgres, Snowflake, BigQuery) and cloud paths via fsspec
  (S3, GCS, Azure, http folders) (old P2.3, P2.5, B2.2).
- The 26 checks running over DuckDB, so `crivo diagnose` works on a 5 GB
  parquet folder on a laptop (B2.2).
- The referee's SQL checks: fan-out, key uniqueness and null keys, grain, the
  second path.
- Relational and temporal correctness (the P7 packets): foreign-key orphans
  and join-aware dedupe (disease 28), the temporal check (disease 27) and
  `Report.temporal`, arithmetic and 3+ column dependencies, end-before-start;
  reconcile shows its excluded keys (decision D13 confirms the P7 resolutions).

**Gate:** our own SQL trap suite on a seeded warehouse (public text-to-SQL
labels are 52 to 66% wrong, so no leaderboard is the gate); false-backed rate
near 0 for SQL answers; diagnose over a 5 GB folder within a stated budget.

## Stage 4: labelling at scale

**Goal:** questions over free text, with the model labelling and code counting.

- The System 1 `decide()` seam, local-first (R4.3); `crivo.label` as a managed
  operator with dedup, PII screen, gate, cache, validation, spot-check (R4.4 to
  R4.6). Absorbs free-text categorization (B4.5).
- PII names and addresses (Presidio-class) for the label screen, and masking as
  a gated fix (B0.1).
- The intent-check pre-filter, adopted only on measured mismatch recall.
- Decisions: local model size (D14), Jev opt-in, the privacy rule for sending
  distinct values to a model (D15).

**Gate:** a tabular OOLONG suite (free-text column plus aggregate questions);
the intent-check evaluation; label agreement on spot-checks published.

- PyPI: name check, the owner's token, 0.1.0 (old P4.2, LG4; decision D19);

**Gate:** the `docs/QA.md` suite run by an outside agent driving crivo; the
